# Sonic 애니메이션 뷰어 PRD

## 1. 문서 목적

`sonic-sprite.png`에 포함된 Sonic의 동작 애니메이션을 순서대로 재생하는 학습용 뷰어를 만든다.

## 2. 제품 범위

- 대상 파일: `Labs/LEC09/sonic_animation_viewer.py`
- 사용 기술: Python, pico2d
- 리소스: `Labs/LEC09/sonic-sprite.png`
- 단일 파이썬 파일로 구현한다.
- 사용자의 입력 없이 애니메이션을 자동 재생한다.

## 3. 사용자와 사용 시나리오

이 프로그램은 스프라이트 시트와 2D 애니메이션의 동작 원리를 확인하려는 학습자를 위한 도구다.

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 프로그램은 창을 열고 첫 번째 동작의 첫 프레임을 보여 준다.
3. 현재 동작의 프레임을 순서대로 재생하고, 동작이 끝나면 처음부터 반복한다.
4. 현재 동작을 5회 완료하면 1초간 마지막 프레임을 유지한다.
5. 다음 동작으로 이동하며, 모든 동작이 끝나면 다시 첫 동작으로 돌아간다.
6. 사용자가 창을 닫으면 프로그램이 정상 종료된다.

## 4. 핵심 기능

1. 스프라이트 시트의 모든 동작 애니메이션을 정해진 순서로 재생한다.
2. 각 동작은 5회 반복한다.
3. 한 동작의 반복이 끝나면 1초 동안 멈춘 뒤 다음 동작으로 넘어간다.
4. 마지막 동작까지 재생하면 첫 동작부터 다시 시작한다.
5. 프레임은 스프라이트 시트에서 해당 동작 영역만 정확히 잘라낸다.
6. 화면에서 캐릭터가 충분히 크게 보이도록 원본보다 확대해 그린다.

## 5. 애니메이션 데이터 설계

- 스프라이트 시트의 각 동작은 하나의 애니메이션 단위로 정의한다.
- 각 애니메이션은 프레임 목록을 가지며, 프레임 하나는 최소한 다음 정보를 포함한다.
	- 스프라이트 시트 안의 왼쪽 아래 기준 `x`, `y` 좌표
	- 잘라낼 영역의 `width`, `height`
- 프레임 목록의 순서가 실제 재생 순서가 된다.
- 동작별 프레임 수가 다를 수 있으므로 고정된 열 개수에 의존하지 않는다.
- 좌표와 크기는 이미지의 다른 행 또는 인접 동작이 포함되지 않도록 프레임 단위로 검증한다.
- 모든 동작 데이터는 `sonic_animation_viewer.py` 안에서 한 곳에 모아 수정하기 쉽게 관리한다.

## 6. 재생 설계

- 애니메이션 목록은 동작별 프레임 좌표와 프레임 수를 명시적으로 관리한다.
- 프레임 전환은 시스템 프레임 수가 아니라 경과 시간으로 처리한다.
- 기본 프레임 간격은 상수로 정의하고, 모든 동작에 동일하게 적용한다.
- 현재 동작, 현재 반복 횟수, 현재 프레임은 하나의 재생 상태로 관리한다.
- 프레임 시간이 지나면 다음 프레임으로 이동하고, 마지막 프레임 뒤에는 해당 동작의 첫 프레임으로 돌아간다.
- 한 동작의 반복 횟수가 5회가 되면 프레임을 유지한 채 대기 상태로 전환한다.
- 대기 시간은 1초로 고정한다.
- 대기가 끝나면 반복 횟수를 초기화하고 다음 동작의 첫 프레임부터 재생한다.
- 마지막 동작의 대기가 끝나면 다음 동작을 첫 동작으로 순환시킨다.

### 재생 상태

프로그램은 다음 상태값을 유지한다.

- `animation_index`: 현재 동작의 목록 위치
- `frame_index`: 현재 동작 안의 프레임 위치
- `repeat_count`: 현재 동작을 완료한 반복 횟수
- `state`: 재생 중 또는 동작 사이 대기 중인지 나타내는 상태
- `elapsed_time`: 현재 프레임 또는 대기 상태가 유지된 시간

## 7. 프로그램 구조

- 초기화: pico2d 창, 이미지, 화면 크기와 재생 상수를 준비한다.
- 입력 처리: 창 닫기 이벤트를 확인하고 종료 여부를 결정한다.
- 업데이트: 경과 시간을 누적해 프레임, 반복 횟수, 동작 순서를 갱신한다.
- 그리기: 현재 프레임의 좌표로 스프라이트를 잘라 화면 중앙에 확대해 그린다.
- 종료 처리: 이미지와 pico2d 창을 닫는다.

함수와 변수 이름은 역할이 드러나도록 작성하며, 애니메이션 데이터와 재생 로직을 분리해 좌표를 수정해도 상태 로직이 바뀌지 않게 한다.

## 8. 화면 및 실행 조건

- pico2d 창을 열고 중앙에 확대된 Sonic을 표시한다.
- 창 크기는 캐릭터 확대 표시와 여백을 고려해 정한다.
- 캐릭터는 화면 중앙을 기준으로 배치하고, 확대 배율은 모든 프레임에서 동일하게 유지한다.
- 배경과 캐릭터가 명확히 구분되도록 구성한다.
- 창 종료 요청에 정상적으로 응답하고 리소스를 정리한다.
- 실행 위치가 달라도 `sonic-sprite.png`를 안정적으로 찾을 수 있도록 리소스 경로를 관리한다.
- 이미지 로드에 실패하면 원인을 확인할 수 있는 오류를 출력하고, 잘못된 프레임을 그리려 하지 않는다.

## 9. 제한 사항 및 품질 기준

- 외부 애니메이션 라이브러리를 추가하지 않고 pico2d의 기본 기능을 사용한다.
- 기능 구현에 필요하지 않은 메뉴, 사운드, 캐릭터 조작 기능은 범위에서 제외한다.
- 프레임 좌표를 자동 추정하는 기능은 구현하지 않으며, 시트 확인 후 검증된 데이터를 사용한다.
- 한 파일 구조를 유지하되, 전역 상태의 이름과 변경 지점을 명확히 한다.
- 프레임 전환과 대기 시간은 매 프레임의 경과 시간을 기준으로 동작해야 한다.

## 10. 완료 기준

- 프로그램 실행 시 오류 없이 창이 열린다.
- 스프라이트 시트의 각 동작이 누락 없이 재생된다.
- 한 동작이 정확히 5회 재생된 후 1초 대기한다.
- 마지막 동작 이후 처음 동작으로 자연스럽게 반복된다.
- 프레임 경계 밖의 다른 동작이나 불필요한 이미지가 표시되지 않는다.
- 캐릭터가 화면에서 식별하기 충분한 크기로 보인다.
- `sonic_animation_viewer.py` 외에 실행에 필요한 별도 소스 파일이 없다.
- 파일을 `Labs/LEC09`에서 실행하거나 프로젝트 루트에서 실행해도 이미지가 로드된다.
- 프레임 속도나 창 크기를 조정해도 애니메이션 순서와 반복 규칙이 깨지지 않는다.

## 11. 단계별 개발 및 커밋 계획

각 단계는 동작을 확인한 뒤 하나의 의미 있는 커밋으로 남긴다.

1. 실행 환경과 파일 구조 확인
2. pico2d 창 열기
3. 창 종료 처리 추가
4. 스프라이트 이미지 로드
5. 이미지 중앙 표시
6. 이미지 확대 표시
7. 첫 동작의 프레임 영역 정의
8. 첫 동작의 프레임 전환 구현
9. 시간 기반 프레임 갱신 적용
10. 동작별 프레임 데이터 구조화
11. 두 번째 동작 추가
12. 전체 동작 목록 등록
13. 동작 종료 및 다음 동작 전환
14. 동작별 5회 반복 처리
15. 반복 종료 후 1초 대기 처리
16. 마지막 동작에서 첫 동작으로 순환
17. 모든 프레임 좌표 및 경계 검증
18. 실행 경로와 리소스 경로 안정화
19. 재생 속도와 화면 배치 조정
20. 전체 시나리오 테스트 및 문서 정리

## 12. 테스트 시나리오

- 실행 직후 첫 동작의 첫 프레임이 표시되는지 확인한다.
- 각 동작이 정확히 5회 반복되는지 세어 본다.
- 동작 사이에 약 1초의 정지가 있는지 확인한다.
- 모든 동작을 본 뒤 첫 동작으로 돌아오는지 확인한다.
- 각 프레임에 다른 동작의 일부가 섞이지 않는지 확인한다.
- 창 닫기와 일반적인 다른 실행 위치에서의 실행을 확인한다.

### 세부 검수 항목

- 프레임 목록의 첫 프레임과 마지막 프레임이 의도한 동작에 속하는지 확인한다.
- 동작 전환 시 첫 프레임이 누락되거나 이전 동작의 프레임이 한 번 더 나오지 않는지 확인한다.
- 5회 반복을 완료하기 전에는 다음 동작으로 넘어가지 않는지 확인한다.
- 1초 대기 중에는 프레임이 변경되지 않는지 확인한다.
- 장시간 실행해도 프레임 인덱스가 범위를 벗어나거나 재생이 멈추지 않는지 확인한다.
- 창을 닫을 때 예외가 발생하지 않고 프로세스가 종료되는지 확인한다.
